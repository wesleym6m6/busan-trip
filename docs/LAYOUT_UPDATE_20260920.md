# 行程內容排版調整

使用者在前一輪內容更新後表示「內容不錯但排版有點紊亂，感覺就是把文字放進去而已」，明確要求改善排版。本次是既有卡片的閱讀層次調整，原定案美術保留，沒有更換行程、餐廳、預約或路線。

## 畫面檢查與決定

修改前在 Codex In-app Browser 的 390px 畫面確認：時間欄使標題與提示過窄；展開後的場所介紹、店家規則與當次安排使用同一段文字樣式；備案頁把所有店家規則直接攤開，缺乏比較時的重點。

1. 時間與狀態置於卡片上方，標題及行動提示使用完整寬度。停留預算和地圖使用同一操作列。
2. 展開後先呈現場所介紹，再列現場資訊，當次安排用淡底區塊分段。資訊仍全部取自既有 JSON，不依文字內容猜測欄位。
3. 備案各餐廳使用一致的名稱、特色、用餐資訊與地圖位置；特色直接可見，營業與點餐資訊可獨立展開。選擇備案的條件留在各組下方。
4. 每日大標題使用平衡換行；地圖和新增的展開控制至少 44px 高，保留鍵盤焦點及減少動態支援。

## 實作範圍

- `ApprovedTrip.tsx` 傳遞分開的場所欄位，不再預先串成一個 note。
- `ContentCards.tsx` / `content-cards.css` 集中管理這兩種內容卡。
- `view.tsx` 沿用既有頁面外框及四分頁，只改卡片呼叫、標題換行和備案標題。
- `ContentPresentation.test.tsx` 驗證備案可獨立展開，且地圖仍可使用；既有時間限定詞、共用內容、日期與打包保存測試保留。
- 來源 JSON、資料 schema、素材、海面／海鷗動畫及部署設定不變。
